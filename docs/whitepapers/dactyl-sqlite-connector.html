Dactyl's SQLite Connector Boundary

The local route is a real SQLite database. Dactyl keeps the application-facing operation, result, and error boundary while SQLite owns file compatibility and execution.

Boundary

application -> Dactyl facade -> SQLite file
                         \-> Neon/Propodus HTTP route

Dactyl owns route selection, parameter binding, access mode, atomic batches, row normalization, generated-key results, schema projection, and stable error categories. Decapod owns schema and migration policy. Propodus owns hosting, authentication, tenancy, authorization, retries, and idempotency.

Local compatibility

Read/write opens use SQLite's normal flags and create the requested path when needed. Read-only opens require an existing file. SQLite supplies locking, journaling, crash recovery, and the SQL surface; Dactyl configures the busy timeout and maps native outcomes to backend-neutral errors.

Proof

tests/sqlite_existing.rs opens a checked-in Decapod SQLite fixture without conversion, verifies values and schema, updates it, and reopens it. The storage contract covers atomic rollback, constraints, foreign keys, read-only behavior, and a native SQLite lock timeout.
